### Task 6.1 - Understand the basic Git workflow
| Git operation | What it does in your own words |
| :--- | :--- |
| Check repository status | Shows which files are changed, added, or untracked |
| Stage selected changes | Prepares specific files to be saved in the next commit |
| Create a commit | Permanently saves the staged changes to the timeline |
| View commit history | Shows the log of all past commits and who made them |

**Staging vs Committing:** Staging (`add`) is like putting items in a shopping cart, while committing is actually checking out and saving them permanently to the project history.

### Task 6.3 - Branches and Pull Requests
* **What is a branch?** It is a parallel workspace where you can make changes without breaking the main code.
* **What is a Pull Request?** It is a request to merge your branch back into the main branch, letting others review the code first. Useful for teamwork so nobody accidentally ruins the main project.

### Task 6.4 - Git command glossary
* **Initialise a repository:** `git init` - turns a normal folder into a Git repo.
* **Check status:** `git status` - checks what files are modified.
* **Stage changes:** `git add` - readies a file to be committed.
* **Commit changes:** `git commit` - saves the changes.
* **View history:** `git log` - shows previous commits.
* **Create/list branches:** `git branch` - lists branches or makes a new one.
* **Switch branches:** `git checkout` or `git switch` - moves you to another branch.
* **Publish changes:** `git push` - uploads your local commits to GitHub.
* **Retrieve changes:** `git pull` - downloads the latest remote commits to your Mac.
